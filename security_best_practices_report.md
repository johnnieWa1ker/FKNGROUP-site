Проверены исходники четырёх страниц, генератор, все 29 словарей, клиентский JavaScript, CSS, локальный сервер, сборка и GitHub Actions. Внесены локальные исправления. Критических и высоких подтверждённых уязвимостей в коде не обнаружено. Полное юридическое соответствие **не подтверждено**: остаются фактические и организационные вопросы. Изменения не опубликованы.

## Приоритетные открытые вопросы

### 01 — Высокий приоритет выпуска: публичный домен показывает другой сайт

На момент проверки HTTPS GET `https://fkngroup.pro/` вернул парковку Рег.ру: `meta name="parking" content="regru-rdap"`, текст «Домен зарегистрирован и припаркован», подключения Yandex RTB и Metrika с `webvisor:true`. HEAD: HTTP 200, server `openresty`. Это не страницы репозитория. Наличие скриптов подтверждено по HTML; фактические отправки событий не исследовались.

Следствие: локальные Privacy/Terms сейчас не описывают содержимое домена; заявление об отсутствии аналитики относится только к этому проекту. Необходимо проверить DNS и Settings → Pages → Custom domain, убрать парковку и проверить домен после публикации. Настройки регистратора, DNS и аккаунта GitHub не изменялись. HTTPS-заголовки парковки не считаются результатом проверки безопасности будущего GitHub Pages сайта.

### 02 — Высокий приоритет выпуска: Privacy требует подтверждения практик

Исходная Privacy состояла из общего абзаца. Подготовлен расширенный двуязычный черновик с описанием оператора, почты, хостинга, целей, оснований, хранения и прав. GitHub Pages и iCloud Mail подтверждены владельцем. Не установлены:

- конкретный срок или реально применяемые критерии удаления переписки, исключения и порядок удаления резервных копий;
- роли и юридические лица провайдеров, применимые договоры, страны обработки и правовое основание/гарантии международных передач;
- фактическое выполнение запросов субъектов, реестр обработки, ответственные и процедура реагирования на инциденты;
- актуальность реквизитов по выписке и точность грузинской юридической редакции.

`data/company.json:10`: `privacyConfirmed` переключён на `false`. Это сознательно блокирует `build:release` и, следовательно, автоматическое развёртывание через workflow при пуше. Preview работает; HTML помечен noindex. Не включать флаг только ради зелёной сборки. Черновик не заменяет подтверждение реальной практики и проверку грузинским юристом.

Основания проверки: [закон Грузии о персональных данных](https://www.matsne.gov.ge/en/document/view/5827307), статьи 4, 5, 13–22, 24, 27–30, 36–37. Информирование включает основания, получателей, хранение и международные передачи. Текущий текст закона называет State Audit Office of Georgia органом обжалования. Публикация текста сама по себе не выполняет организационные обязанности.

### 03 — Средний приоритет: грузинская доступность сведений

В исходнике грузинский словарь загружался только JavaScript, а значения адреса/правовой формы оставались английскими. Теперь на Company, Privacy и Terms встроены грузинские реквизиты; Privacy/Terms содержат английские и грузинские разделы без JavaScript, якорные ссылки и дату редакции. Перевод адреса и формы хранится в `data/company.json`, отдельно от шаблона. Официальное грузинское наименование не выдумывалось: сохранено предоставленное `FKN COMPANY LLC`.

[Закон об электронной коммерции](https://matsne.gov.ge/en/document/view/5825902?fullscreen=1&impose=parallelEn), статьи 4 и 10: информация о поставщике должна быть легко доступна и предоставляться на государственном языке. Для текущей витрины выбран консервативный подход; применимость норм к конкретным услугам следует уточнить при запуске продаж.

Отдельные возвраты, checkout-условия и платёжная оферта не добавлены: в проверяемом проекте нет покупки, подписки, оплаты или пользовательских аккаунтов. При появлении продаж нужен новый анализ требований к преддоговорной информации и потребительским правам. Cookie-баннер не добавлен: в коде нет необязательных трекеров; это не вывод о парковочной странице.

## Безопасность: исправлено

### 04 — Низкая, локальная утечка скрытых файлов/символических ссылок

`scripts/server-path.mjs:5`, `scripts/dev.mjs:32`. Старое выражение допускало `/assets/.env`; проверка пути не препятствовала чтению файла через символическую ссылку в публичном каталоге. Сценарий требует наличия такого файла/ссылки и доступа к запущенному локальному серверу. Сервер слушает только 127.0.0.1; признаков существовавшей утечки или размещённых секретов не обнаружено.

Теперь скрытые сегменты запрещены после нормализации пути, а реальный путь должен совпадать с разрешённым. Сборка дополнительно отклоняет скрытые файлы и символические ссылки в assets (`scripts/validate.mjs:24`). Регрессионные тесты создают временные `.env` и ссылку на закрытые данные и проверяют HTTP 404; отдельный тест проверяет отказ в упаковке.

### 05 — Низкая, усиление защиты браузера

`scripts/render-html.mjs:36`: добавлены CSP и Referrer Policy. Скрипты, стили, изображения и fetch ограничены своим origin; запрещены object, подмена base и отправка форм. Inline-скрипты не используются. Имеющиеся `innerHTML` получают только константную разметку; переводы выводятся через `textContent`, значения шаблонов экранируются. Подтверждённого XSS-пути не найдено.

CSP — дополнительный слой защиты, а не исправление доказанного XSS. Meta CSP не обеспечивает `frame-ancestors`; для запрета встраивания необходим HTTP-заголовок на совместимом хостинге/прокси. Настройки TLS, заголовки будущей публикации и защита аккаунтов вне проверки исходников.

### 06 — Низкая, проверки конфигурации и переводов

`scripts/validate.mjs:20`: релизные подтверждения принимаются только как boolean `true`, а не truthy-строки. HTTPS URL с логином/паролем отклоняются. `script.js:133`: словарь проверяется до применения; повреждённые данные сохраняют предыдущий язык. Добавлен явный список разрешённых языков перед fetch.

Наличие дефектов конфигурации не означает возможность удалённого изменения конфигурации посетителем. Это профилактика ошибок при редактировании исходников. Поиск типовых токенов/приватных ключей в рабочем исходном дереве совпадений не дал; история Git и секреты удалённых аккаунтов не сканировались.

## Архитектура

Статические HTML/CSS/ES-модули подходят четырём информационным страницам. Runtime/npm-зависимостей нет; здесь отсутствуют серверные сессии, база, SQL, авторизация и формы, поэтому соответствующие классы серверных атак не применимы к этому репозиторию. Переписывание на React/Next.js не обосновано.

Сильные стороны: одна конфигурация компании, генерация HTML, экранирование, ограниченный состав сборки, английский fallback, контроль ключей переводов, гонки загрузки языков защищены номером запроса. Юридический контент вынесен из шаблона в `scripts/legal-content.mjs`; dev-сервер отслеживает его изменения.

Осталось для следующей итерации: разбить длинные шаблонные строки на читаемые компоненты, систематизировать CSS вместо накопления переопределений, закрепить GitHub Actions по проверенным SHA с автоматическими обновлениями, проверять точный Node 22 в CI. Текущий локальный Node — 23.11.0; GitHub Actions объявляет Node 22. Политики защиты веток, MFA и доступов к репозиторию не проверялись.
